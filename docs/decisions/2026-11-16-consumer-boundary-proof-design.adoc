== Decision 1: preserve boundary semantics, not spelling conventions

Storage normalization and header rejection are distinct operations.
The first maps CR/LF/CRLF to a canonical line-token representation; the
second rejects the presence of either forbidden octet. Sholes proves that
normalization preserves that presence. Its stronger counterexample proves
that every LF-canonical stream defeats a CRLF-pair-only detector.

Do not insert normalization ahead of the current Proven Zig predicate as
a repair. Keep the authoritative operation in Idris and make Zig marshal
and call it. Adding a second correct-looking Zig scan would leave the
architecture's duplicated semantic authority in place.

For the raw pointer/length ABI, specify the operation over an exact byte
sequence. Do not route it through a NUL-terminated string: `NUL, CR`
would otherwise permit truncation before the forbidden byte. Use an
Idris byte-sequence entry point and explicit length-preserving marshaling.
Relating that entry point to the existing String predicate is a separate
lemma about the chosen encoding; RefC code generation alone is no proof.

Preserve current null-pointer error behavior even at length zero until an
explicit ABI revision. A non-null empty region returns success/false.
Accessible memory for the complete declared length remains a caller
precondition; a null test cannot establish pointer validity. Record
read-only access, lifetime and alias conditions in the contract.

== Decision 2: routes are plans until a transport is registered

Separate `protocolTag` decoding, planned route selection, registered
capability, invocation and outcome. They are five different judgments.
A successful route lookup must not be treated as a successful API call.

Use a registration witness tied to the exact transport implementation
and configuration, rather than a Boolean named `implemented` that is
true merely because an enum constructor exists. An empty registration
set is the initial truthful state of unified-api-adapter. Known but
unavailable protocols return Unsupported; unknown byte tags return
InvalidParam. Invocation errors remain errors, preserving payload and
resource ownership contracts.

For the proof model, use a finite byte type and a total decoder whose
forward and reverse laws are both established. The current Idris
`Bits8` round-trip proves encode-then-decode for nine constructors;
it does not establish decode-then-encode for arbitrary primitive bytes.
Sholes' finite reflection coverage technique is reusable for that
closed 256-value domain. It does not supply an Idris `Bits8` equality
reflection theorem. The primitive-to-finite conversion still needs
its own implementation relation and exhaustive executable comparison.

== Decision 3: extend Atoma through a checked semantic relation

Retain the closed, fail-closed frontend. Add only the constructs demanded
by the first consumer slice: immutable byte-region views, bounded reads,
guarded iteration, finite state, explicit status/result construction and
calls with supplied contracts. Reject unsupported operations and imports.
Do not infer correctness from a copied theorem about a similar model.

The required commuting argument has four links:

. The exact source function and transitive imports elaborate to the
  accepted typed control-flow model, including all exceptional paths.
. Lowering preserves the model's input/output relation and definedness
  obligations: bounds, arithmetic, ownership, aliasing and state transitions.
. The generated verification conditions imply the selected consumer
  contract; replay checks those conditions against a source-derived statement.
. The compiled ABI wrapper implements the accepted relation under its
  recorded runtime/compiler/target assumptions.

Use per-function translation validation as the next implementation
approach, backed by explicit Agda semantic rules and corresponding
replay witnesses. A general verified Zig compiler is outside v1.
Until link 1 and the relevant ABI portion of link 4 have evidence, keep
the consumer result INCOMPLETE, even if every model theorem replays.
Compiler trust must remain explicit in the eventual supported v1 profile.

The practical diversity is intentional: a header predicate exercises
byte-region and encoding boundaries; Sholes streaming adds persistent
state across splits; adapter dispatch adds closed decoding, registration
and external effects. A single scalar arithmetic example covers none
of those new boundaries.

== Reuse from Mathesis and ownership of new results

`FeatureReachability.Monotone.reach-mono` is directly reusable for a
capability/dependency graph if adding registrations only adds edges.
Its `absent-below` corollary can justify absence under smaller configurations.
The instantiation must supply `edge-mono`, a fixed implementation graph
and a fixed target/configuration context. Revocation, mutually exclusive
flags and runtime failures invalidate a naive monotonicity argument;
they are not covered by turning on every feature.

`Applied.Status.zipWith-needs` and `missing-uncovered`, together with
`Applied.Missing`, provide an existing design pattern for preserving
missing evidence and preventing unjustified upgrades. Their concrete
financial evidence statuses are not PWG grades or Atoma acceptance levels.
Generalizing a dependency-evidence theorem requires a new abstraction
and a comparison of statements, not relabeling those constructors.

Sholes owns its line-ending and streaming laws. Proven owns the concrete
Idris/RefC/Zig boundary. unified-api-adapter owns its protocol and
transport contract. Atoma owns Zig semantics and lowering adequacy.
Mathesis indexes pinned home-repo receipts and may own genuinely generic
finite-reflection or evidence-composition theorems once their admission
record names the actual dependants. Do not copy application proofs into
Mathesis merely to raise a catalogue count.

ECHIDNA owns reusable evidence/replay plumbing. Use its stable published
contract when available; do not duplicate that acceptance kernel or
depend on another task's uncommitted implementation.

== Witness identity and limits

Bind receipts to source/import hashes, exact contract statement, frontend
version, Zig/Idris/RefC versions, target triple and ABI, capability
configuration, checker executable/version, assumptions and proof inputs.
An accepted solver answer or a passed test is not an independent proof.
Missing obligations and unavailable checkers remain explicit failures
or INCOMPLETE results, never empty successful obligation lists.

Sholes currently uses source-reviewed hand re-proofs in Lean and Rocq.
The three kernels accept corresponding mathematics, but automatic
statement correspondence remains open. Finite Wire lemmas now also have checked Lean and Rocq legs. Full Cubical is a separate profile, not a new independent
kernel. The installed Lean4Lean executable failed on incompatible object
headers; no successful checker leg is claimed for it.

== Next implementation packets and acceptance criteria

Follow-up implementation evidence: Proven now has a reachable Idris byte-state
kernel and a native RefC bundle path. The consumer diagnostic links that actual
library; the five original cases agree. Its stronger ABI corpus covers all byte
pairs and rejects an always-clean compiled mutant. This closes the observed
behavioral disagreement, not the unproved source/compiler refinement relation.

The adapter's finite decoder now has both decoding laws and its partial
registration model has a no-fabricated-handler theorem. Its executable RefC
matrix covers all 256 tags and four registration states. The actual Zig
registration table and network transports are still pending. Reproduce that
matrix at unified-api-adapter commit `259eff356e72fde2dadb1e144442f7a736da3601`
with `bash scripts/check-registry.sh`; see
link:https://github.com/hyperpolymath/unified-api-adapter/blob/259eff356e72fde2dadb1e144442f7a736da3601/scripts/check-registry.sh[the pinned registry gate].
The link:../../tests/consumer-boundary/README.adoc[consumer diagnostic]
documents only the Proven experiment and its explicit receipt boundary.

is no justified v1 date yet: the remaining risk lies in source/ABI
refinement and real transport effects, not in counting theorem files.
