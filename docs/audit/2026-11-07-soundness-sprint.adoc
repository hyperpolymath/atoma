= Atoma soundness repair: evidence and limits
:revdate: 2026-11-07

Baseline: `8d7898572285c2abe9fe0f3dfd3e892ec1a211f2` (main, 22 October).
This report describes the repair working tree and its reproducible gates.
The PR's hosted CI artifact binds the exact tested commit; local evidence
does not replace that run. Evidence files below live beside this report in
`2026-11-07-soundness-sprint/`.

== Review boundaries and remaining work

* No Zig-to-Agda refinement theorem, checked general VC generator, general
  alias/loop/call model or Dedukti/Coq/Lean4 replay was added.
* The u8 experiment is a deliberately tiny, exhaustively checkable language;
  its parser, lowering, emitter, evaluator and compiler remain trusted.
  Passing the general token screen still proves no semantic subset membership.
* The frame repair assumes a valid writable output lease disjoint from input,
  handle and iterator. It checks null pointers, not arbitrary pointer validity.
* This PR does not mint the inherited deed, edit licences, fix all template
  workflows, certify standards compliance or publish a release.
* CI bootstrap dependencies are not a fully reproducible Guix closure. The
  bounded deviation must be retired or reviewed before release.
* Sibling plans were compared for reuse opportunities; their engines were not
  audited or modified. See `../decisions/ATOMA-SIBLING-TRANSFER.adoc`.

== Hosted validation

https://github.com/hyperpolymath/atoma/pull/2[PR #2] carries hosted validation.
The initial workflow linter found missing SPDX metadata on the newly created
workflow; new files now carry the repository's existing code/document
declarations. Bootstrap and installation also use the same Idris prefix.
No existing licence terms or declarations are changed.

The official lock generator (v0.4.1), when run globally, removed reusable-
workflow entries and made `scripts/check-lock-sync.sh` fail. Those generated
changes were reverted. The three inherited frozen-lock warnings remain explicit
estate debt requiring a coordinated fix in the canonical workflow/lock tooling;
neither the existing lock-sync gate nor its coverage was weakened to get green.

Review also identified inconsistent I/O exit codes in the new source commands.
Missing/oversized/malformed input and failed output writes now return 3;
counterexamples and unsupported constructs return 1. A failed stdout write
is never silently discarded. An explicit empty-module guard supplements the
Agda checker's existing empty-registry rejection.

The active https://github.com/hyperpolymath/atoma/rules/26764574[Atoma soundness
ruleset] requires `Atoma soundness gate` from GitHub Actions (integration
15368) on `main`, with strict up-to-date checking and no bypass actors. The
existing Branch-Floor rule remains active. Hosted proof-tool execution was
pending while preparing this report; the PR description/final update records
the observed result and unrelated failing estate checks. A local pass is not
a substitute for that result.

Commits use GitHub's authenticated automatically signed commit API. Signature
validity was checked through the API and independently with the official
GitHub public signing key in an isolated keyring (`SIGNATURE_STATUS=G`);
the user's normal keyring and signing configuration were not changed.

The pinned hosted profile passed in
https://github.com/hyperpolymath/atoma/actions/runs/42395104592[run 42395104592]
at commit `63018ee9c73bb1e2d3a436ef067cfb3c4e82c374`, including artifact upload.
The final PR head also adds the CLI I/O and empty-registry falsifiers; its run
must pass independently and is linked in the PR description.

== Follow-up: regression recovery and merge-readiness repair

Commit `b980405` applied an obsolete review suggestion inside an existing catch
block. The duplicate handler did not compile; the required gate correctly failed
before claiming success. Commit `f87b740` repairs the handler, retains exit 3 for
I/O/parse failures and extends failed-output checks to the successful
`source-check` report. Hosted run 42403751163 passes. The checked input manifest
has been regenerated from the repaired implementation, not copied from the
earlier passing CLI. The normative spec no longer claims an executable Idris
foreign binding.

The follow-up also renders identity/contact metadata using the inherited
canonical `repo-init` in a disposable review tree. Its provenance resolver
recovered the original template commit `889f7f79aa99` from Atoma's root commit.
The actual implementation, historical Atoma plan and evidence were preserved;
template-only overlay/seed files were removed as prescribed by the initializer.
Atoma now declares experimental maturity and the Formal Verification & Proofs
clade, with repository creation dated 2026-10-22. This does not register a new
external clade record or certify standards compliance. Existing licence texts
and licence identifiers are unchanged; REUSE contact metadata is rendered.

Reusable workflow references follow the standards repository's transfer to
`metadatastician/standards`, retaining the same immutable commit. Lock metadata
records its current owner ID and `main` as the resolving branch; the retained
standards/cicd-suite commits were checked as ancestors of their respective main
branches. Workflow closure remains checked by the unchanged lock-sync gate.
The Actions allow-list admits only the exact configured standards workflow
commits and the existing pinned EditorConfig release; GitHub-owned and verified
publisher policy remains enabled. No required check or protection was removed.

The Windows `gh actions-lock` global verification still misclassifies job-level
reusable refs as stale. Its scoped action verification and the separate
job-aware closure check are recorded distinctly; a global pass is not claimed.
The existing SonarCloud project is `hyperpolymath_zigprove` (Atoma's previous
name); the local scanner configuration now targets that project rather than
the template's project.
