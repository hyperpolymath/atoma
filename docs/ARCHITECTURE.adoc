= Atoma architecture
:revdate: 2026-11-07

Atoma's central invariant is that evidence may claim no more than the source,
semantics and checkers it actually covers. A failed or missing check must not
produce a successful verification status.

== Components and data flow

* `tools/atoma/src/source.zig` parses and lowers the closed u8 source pilot,
  evaluates its finite domain and emits QF_BV obligations. This lowering and
  Zig's compiler are still trusted; there is no source-refinement theorem.
* `tools/atoma/src/frontend.zig` screens general Zig syntax and annotations.
  Its token screen does not establish semantic subset membership.
* `examples/atoma/frame-v1/abi` contains the normative Idris contract encoder
  and QTT resource model. `scripts/atoma-check-idris.sh` executes extraction
  and checks it against the canonical contract. There is no live Idris FFI.
* `examples/atoma/frame-v1/src` is the native frame implementation. Its
  poisoned-output tests and target layout witnesses are compiled evidence.
* `verification/atoma/agda` proves the store-free model theorem, separately
  from implementation testing and SMT model obligations.
* `scripts/atoma-gate.sh` rebuilds, checks registered proof coverage and
  collects tool identities, input hashes, verdicts and falsifier outcomes.

Inputs are source files, contracts, proof registrations and tool identities.
The source pilot rejects constructs outside its closed grammar before emitting
an obligation. Outputs are diagnostics, solver inputs and scoped evidence.
Changing a body must change the obligation or invalidate the evidence.

== Trust and cross-cutting concerns

The current ceiling is INCOMPLETE / Warrant. Parser/lowering correctness,
compiler refinement, general memory/alias semantics and independent proof
exchange/replay remain open. An Agda model theorem does not close these gaps.
Pointer validity and disjoint output leases are explicit frame ABI assumptions.

CI treats tool availability, exit status, output delivery, current-source
rebuilding, proof coverage and provenance as interacting correctness concerns.
Both source commands return I/O status 3 if their result cannot be delivered.
The native frame API remains single-threaded.
