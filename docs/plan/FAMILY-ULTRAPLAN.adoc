=== Bespoke: each repository must do it alone

* The front end: parser or compiler adapter for the target language.
* The closed subset and its exclusions.
* The semantics: memory and aliasing (Zig), dispatch and numeric tiers (Julia),
  actors and supervision (Elixir), modules and effects (OCaml), strided domains
  and array loops (Chapel).
* The refinement argument from admitted source to the proved semantics.
* The pilots and the diagnostics for users of that language.

`ATOMA-SIBLING-TRANSFER.adoc` forbids a shared semantic IR until two adapters
show the same meaning. This plan keeps that rule.

== Definition of v1.0.0

`atoma/docs/plan/ULTRAPLAN.adoc` defines seven conjunctive gates. Every
verifier in the family uses the same seven. Only the acceptance text changes.

[cols="1,4",options="header"]
|===
| Gate | Family rule
| Language boundary | A closed, typed subset with stated exclusions. An unsupported construct fails closed.
| Source connection | Obligations come from the body. A change to a body, an import or a target invalidates old evidence.
| Semantics | The semantic rules that the subset needs are proved, and the trusted computing base is published.
| Replay | A source-derived witness passes every kernel that the specification requires. Unknown, timeout, missing and malformed evidence fail closed.
| Practical coverage | Three pilots. A second consumer needs no special case.
| Assurance | Mutants are killed by gates that ran. Evidence is reproducible and bound to source.
| Release and estate | Claims, deed, README and installation are true. The standards V1-GATE audit passes.
|===

`canonry` is a theory library, not a verifier. Its v1 gates are in its own
plan. A repository can release `0.x` versions before it passes all gates.

== Waves: how the six move forward together

A wave closes when each repository has its exit evidence. A repository that
cannot close a wave narrows its subset. It does not skip the wave.

[cols="1,3,3",options="header"]
|===
| Wave | Shared work | Exit evidence in each repository
| W0 Truth and wiring | F1, F2, F4 (first half) | README is true. One project gate runs in CI. Each known hole is closed or is an open obligation in `PROOF-STATUS.adoc`.
| W1 Evidence spine | F3, F6, F7, F5 | The gate uses the evidence kit without a local fork. One benchmark has a baseline from a real run.
| W2 First source-bound obligation | none (bespoke front ends on the shared kit) | One closed function goes from source to obligation to ECHIDNA replay. One body-only mutant is rejected. Receipt status is INCOMPLETE.
| W3 Subset and semantics | F8, F9 | The checked argument covers the admitted subset. An alias, overflow or nontermination counterexample is rejected.
| W4 Kernel chain and grades | F7 (exchange), F10, F11 | End-to-end replay. Adversarial certificates fail. Theory theorems have receipts.
| W5 Pilots and release | F12 | All seven gates pass on the release commit.
|===

W0 is partly done (see "Done in the first session"). W2 is the first wave
that tests the transfer claim: measure time to a valid proof, time to reject a
body-only mutant, adapter size, and the count of kit components reused
unchanged. Re-estimate W3 to W5 from those numbers.

== Models, effort and cost

=== Roles

[cols="1,3,3",options="header"]
|===
| Model | Use it for | Do not use it for
| Fable (advisor) | Plan ratification. Wave gate review. Review of each claim promotion. Review of a cross-repository contract. | Execution. Routine review.
| Opus (lead) | Proof work. Semantics. Refinement arguments. Contract and schema design. Repair of a soundness hole. Review of Sonnet work on a trust path. | CI, template drift, status files (doctrine rule 16).
| Sonnet (executor) | Implementation against a written specification, 3 to 20 files. CI workflows. Adapters. Tests. README and status documents. | Design of a trust rule.
| Haiku (bulk) | Scout pass before each step. Mechanical edits. Template sync. Counts and stale-string sweeps. | Any edit that needs judgment about a claim.
|===

=== Orchestration rules

. Opus leads one wave in one repository at a time. It writes the brief for each Sonnet or Haiku task.
. One writer for each repository tree at a time. Each brief names one allowed tree.
. A Haiku scout runs before each Sonnet or Opus step. It reports blockers in 20 lines or fewer.
. The advisor is called at four points only: plan ratification, the close of each wave, each promotion of a status word, and each change to a shared contract. The input is evidence files, not a narrative.
. A subagent never states that a check passed unless it ran the check. The lead reruns one check from each report.
. Work that touches a status word, a receipt, a trust level or a proof goes to Opus, with advisor review.
. Common work (F1 to F12) is done in one repository first. Sonnet or Haiku then replays it in the others from a replay brief.
. Shared code is extracted only after two repositories use the same thing.

== CI/CD design (F4, F5)

Every repository has one project workflow with the same shape. `atoma.yml` is
the reference.

. `actions/checkout`, no persisted credentials, read-only permissions.
. `scripts/<repo>-ci-toolchain.sh`: installs pinned tools and checks each digest.
. `scripts/<repo>-gate.sh`: one fail-closed entry point. A missing tool is a failure, not a skip.
. The gate runs unit tests, project proofs, falsifiers, then the benchmark.
. The evidence directory is uploaded even on failure.
. The job is a required check on `main`.
. After a workflow change, run `scripts/lock-sync-fix.sh`, then `scripts/check-lock-sync.sh`. Do not edit `actions.lock` by hand.

[cols="1,2,3",options="header"]
|===
| Repository | Gate today | Next step
| `atoma` | `atoma.yml`: full gate | Add the replay time and the mutant-rejection time as benchmarks.
| `Apodeixis.jl` | `julia.yml`: package tests on two Julia versions | Add audit throughput on a fixed corpus as a benchmark.
| `quintessence` | none | Add `quintessence.yml` with the Zig unit tests first. Add the suite only after the solvers are pinned and the NIF receipt reproduces.
| `bactrian` | `bactrian.yml`: preflight test | Flip the expected preflight status when WP-00 pins the authorities.
| `canonry` | `canonry.yml`: Agda proof gate | Add the receipt step (F11).

== ECHIDNA coprocessor (F10)

Question from the owner: are these repositories wired to the ECHIDNA
coprocessor layer and its Julia side, `src/julia/coprocessor.jl`, and can that
be done without friction?

Answer: no repository in the family refers to the coprocessor. The wiring is
not possible without friction today. These are the facts, read from the
ECHIDNA source on 2026-11-15:

* The Rust coprocessor layer has 16 kinds. The in-process backends are real code.
* No external entry point exists. The CLI, REST, gRPC and GraphQL interfaces have no coprocessor route.
* `coprocessor.jl` implements 6 `Math` operations. No recipe, container or Julia file starts it. Rust code never constructs the bridge. No round-trip test exists.
* The coprocessor default URL and the ML sidecar default URL both use port 8090.
* The wire format has no version field and no published schema.
* The trust tier of a coprocessor is defined. No code outside the module reads it.
* The ECHIDNA plan (decision D-G) defers the coprocessor trait "until a second consumer needs it".

The verifier family is that second consumer. The path, in order:

. The owner rules on D-G.
. ECHIDNA publishes a versioned contract, `echidna.coprocessor/1`, in the style of `PROVE-RESULT-CONTRACT.adoc`.
. ECHIDNA adds one entry point, for example `echidna coprocessor dispatch --output json`, and a capability probe.
. Trust rule: a coprocessor answer is a hint. It never raises a status word. A prover or an exhaustive check must confirm it.
. The Julia server gets its own port, a launcher and a round-trip test.

First uses that pay for the work:

* `canonry` and `chancel`: exact `gcd` and `lcm` for strided-domain alignment. Use them to search for counterexamples before a proof attempt.
* `Apodeixis.jl`: exact integer and rational cross-checks for the exact numeric tier. Interval arithmetic needs new operations.
* `atoma` and `quintessence`: evaluation of bit-vector counterexamples.

Until the contract exists, each verifier calls ECHIDNA only through
`echidna prove --output json`.

== Stop points

* If a W2 spike fails in a language, narrow the advertised subset or change the architecture. Do not add features.
* If the evidence kit needs a language-specific branch, stop F3 and review the schema with the advisor.
* If a status word would be promoted without a receipt, stop. A grade is derived from receipts. It is never asserted.
