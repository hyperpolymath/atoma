= Atoma — soundness-first plan to v1
:revdate: 2026-11-07
:toc:

Atoma is experimental. The release objective is a useful verifier for an
explicit, closed Zig subset, with source-bound obligations and independently
checked evidence. Frame tests, checked specifications, model proofs and the
finite source pilot are distinct evidence; none is a COMPLETE Receipt.

Run `bash scripts/atoma-gate.sh`. Read
`docs/decisions/ATOMA-SOURCE-TO-PROOF.adoc` before extending verification claims.
The original cards are preserved in `archive/ULTRAPLAN-2026-10-22.adoc`; their
status, estimates and session branch instructions are superseded here.

== Current state and blockers

This repair clears valid writable outputs before wrapper-level errors; tests
start with poisoned bytes. It typechecks the Idris contract and QTT model,
executes Face A extraction, corrects the 14-byte field extent within a
16-byte struct and removes the invalid foreign binding. It screens locally
visible recursion and exercises an actual source-derived u8 obligation.
CI requires all tools, rebuilds current source, checks proof registration,
records digests and exercises missing-tool/stale-executable falsifiers.
The evidence report records observed results; implementation alone is not a pass.

The following gaps remain central:

* The four Agda modules prove a store-free model theorem, not the Zig lowering,
  finite evaluator, full parser, compiler, memory model or resource lifecycle.
* The 14 legacy frame SMT queries are reviewed, partially contract-guarded
  examples, not body-derived proofs. Only `source-vc` implements the new source
  dependency, for a tiny closed fragment; the general token scanner is not a
  semantic subset checker.
* No real ECHIDNA-to-Dedukti/Coq/Lean4 replay chain is demonstrated. Exported
  declarations and admitted skeletons are not checked proof translations.
* Store, loops, aliasing, capabilities, modular calls and source refinement
  remain unproved. There is no sound general Zig verifier yet.
* The inherited deed/arrival pack still describe a template. Estate compliance
  is not certified. CI provisioning has a bounded documented deviation;
  Guix closure and all generic estate workflows are separate outstanding work.

== Definition of v1

All applicable rows must pass on the release commit. They are conjunctive
gates, not a readiness percentage.

[cols="1,4,3",options="header"]
|===
| Gate | Acceptance | Falsifier
| Language boundary | Closed typed subset with transitive imports/calls,
compiler/target/mode, explicit exclusions and assumptions
| An unsupported callee or alias changes behaviour while verification stays green
| Source connection | Body-derived VCs and a checked translation-validation or
refinement argument linking admitted Zig to the proved semantics
| Change a body/import/target/mode and reuse old evidence
| Semantics | Store/framing, finite arithmetic, loops with invariants/variants,
postconditions and capabilities, with a published trusted computing base
| Overlapping write leases, overflow or nontermination is accepted
| Replay | Actual source-derived witness passes all kernels required by the spec;
unknown, timeout, missing and malformed evidence fail closed
| An unproved declaration or admitted theorem produces COMPLETE
| Practical coverage | Parser, resource lifecycle and buffer transformation
pilots, independent review and usable source-located diagnostics
| A second consumer needs demo-specific special cases
| Assurance | Meaningful mutation kills, aspect interactions, reproducible
source-bound evidence, required CI, proof registry and security review
| A bad mutation survives because a gate did not execute
| Release/estate | Honest About/README/deed/claims, supported installation and
standards V1-GATE audit with explicit applicability/dependencies
| Template metadata or model evidence is sold as a production certificate
|===

An experimental 0.x release can precede v1. A standalone checked `.dk` file is
not sufficient for v1. The existing COMPLETE policy is not weakened.

== Sequence, scale and stop points

Planning ranges below are judgments, not measured velocity or commitments.
Re-estimate after R1, with compiler/formal-methods expertise available.

[cols="1,3,1,3",options="header"]
|===
| Stage | Work | Person-weeks | Exit evidence
| R0 | This repair and truthful CI/claims | 1–2 | Gate passes; falsifiers fail for intended reasons
| R1 | Typed frontend, memory and replay spikes | 3–5 | One source-bound function, one alias counterexample, one real ECHIDNA replay
| R2 | Closed lowering, contracts and VCs | 6–10 | Body/import mutations affect obligations; precise diagnostics
| R3 | Store, loops, permissions and refinement | 8–14 | Checked argument covers the practical subset, beyond example tests
| R4 | Exchange, kernel replay, receipts and invalidation | 6–12+ | End-to-end replay; adversarial certificates fail
| R5 | Three pilots, mutation/aspect campaigns, installation/release audit | 5–8 | Published release evidence; all v1 gates satisfied
|===

An initial envelope is about 30–60 focused person-weeks plus contingency, with
some overlap. Two experienced contributors might deliver the restricted v1 in
6–12 months; part-time work scales accordingly. Broad Verus-like coverage is
a separate multi-year programme. The old “kernel chain in 3–6 weeks” estimate
is withdrawn pending R1. Both source-to-semantics and evidence replay are on
the critical path. If either spike fails, narrow the advertised subset or
revise the architecture before expanding features.

== Aspect-oriented work and transfer

Coverage must follow `tools/atoma`, `examples/atoma` and `verification/atoma`;
the scaffold aspect script does not demonstrate coverage of these paths.

* Correctness/contracts: poisoned-output regressions, executable Face A,
  source-derived obligations, body mutations and all-input execution.
* Safety/resources: next prove alias/framing and lifecycle sequences across
  success, parse failure, cleanup, close and double-close.
* Proof integrity: registered sources, no admissions, malformed/missing/stale
  evidence fails, precise status vocabulary and explicit trust boundaries.
* Reproducibility/supply chain: bind compiler/target/options/import closure;
  rebuild, edit source, switch target, invalidate cache and replay.
* Delivery/estate: required scoped CI evidence and honest claims; inherited
  compliance debt stays visible.

Exercise sequences across aspects, not isolated checklists. Record reusable
lessons in `docs/decisions/ATOMA-SIBLING-TRANSFER.adoc`; extract a shared engine
only after a second language demonstrates the same semantic boundary.
