= Atoma — Ultraplan
:subtitle: Execution plan for agents and people · revision 1 · 2026-10-22

[abstract]
--
This is the working plan for Atoma, the verification toolchain specified in
`docs/spec/ATOMA-SPEC.adoc`. The specification says *what must be true*. This
document says *who does what next, in which order, and how anyone — human or
agent — can tell whether it worked*.

It is written to survive the reader's absence of context. A fresh agent with a
cold clone, no network history and no memory of the decisions that produced the
current tree should be able to open this file, run one command, see green or
red, pick up a task, and not repeat a mistake already paid for.

Three properties are deliberate. Every task has an **acceptance command** — not
a description of success, a command whose exit status decides. Every task has a
**falsifier** — the observation that would show the work is wrong even though
the command passed. And every task names its **blocker** honestly, because a
plan that hides a missing toolchain teaches the next agent to fake the result.
--

== How to use this document

=== Reading order

If you are new to the repository, read in this order and stop when you have
enough:

. This section (five minutes).
. <<state>> — what is actually true today, with digests (§2).
. <<gates>> — the gate table; if a gate is red, that is your first task.
. The track you are picking work from (§7–§12).
. `docs/spec/ATOMA-SPEC.adoc` §1 (claims ledger) and §6 (semantics) before you
  touch anything that claims soundness.

If you are resuming work, skip to <<board>> and read the task cards flagged
`in-progress` or `blocked`.

=== Task IDs and status

Task IDs are of the form `<track><number>`: `A` identity and estate, `K` kernel
chain, `T` theory, `S` subset, `C` cost and secrecy, `H` hardening. **IDs are
stable.** Never renumber. If a task is split, the new part becomes `A7b`; if a
task is dropped, its card stays and its status becomes `dropped (reason)` so the
history of the decision survives.

Every card carries a status line with one of five values:

[cols="1,3", options="header"]
|===
| Status | Means

| `todo` | Not started, not blocked. Available to whoever gets there first.
| `in-progress` | Someone has claimed it. The claim is the commit, not a message.
| `blocked` | Cannot proceed without the named thing. Do not stub around it.
| `done (evidence: …)` | The acceptance command was run and its output is quoted in the commit or the receipt.
| `dropped (reason)` | Deliberately not doing it. The reason is part of the record.
|===

`blocked` is a first-class outcome. A task blocked on a missing binary is *not*
"done for now", and the receipt must not be nudged upward to make the board look
better. The estate has a phrase for the failure this prevents: a gate that
cannot run must never report OK.

=== The seven rules

. **No silent green.** Every claim is a field in a receipt or a line of gate
  output. If a tool is absent, the gate prints `not-run` and the status stays
  `INCOMPLETE (Warrant)`.
. **The specification is the source of truth for *what*; this plan is the source
  of truth for *when*.** If they disagree, the specification wins and this plan
  gets fixed in the same commit.
. **One name.** Atoma, everywhere: binary, directories, contract domains, wire
  magic. If a `zigprove` or `zp_` token appears, it is a bug, not a legacy.
. **Never invent the solver runner.** ECHIDNA dispatches Why3/z3/cvc5 and owns
  the Alethe→Dedukti road. Atoma produces obligations and consumes certificates.
  A second runner is a second thing to trust.
. **Watch the test fail.** Before trusting a gate, break the thing it guards and
  confirm it goes red. This is written down because four gates in this repo's
  history could not fail (§15).
. **Small trusted tree, replaceable untrusted tree.** CLI, canonicaliser, VC
  generator: replaceable. `Core.agda`, `Soundness.agda`, the Idris2 contract, the
  kernel verdicts: not.
. **Ask before you mint.** Anything that rewrites repository identity
  (`just repo-init`), force-pushes, or changes visibility is an owner action.
  Agents prepare the change and hand it over.

* No mutation **kill** score. The 11 distinct artefacts are the easy half; the

* No refinement theorem. `soundness` relates two Agda functions. The step to a
  compiled Zig function is reviewed, not proved, and is non-claim N3 (§6.4).
* `atoma check` is a token scan. It resolves no names, evaluates no `comptime`,
  computes no layout. It is not a type checker and must not be described as one.

=== The four structural gaps

These are why the plan exists. They are not bugs; they are the distance between
"the design is specified and Phase 0 runs" and "the tool is what it says".

. **Identity.** 88 tracked files still carry `{{PLACEHOLDER}}` tokens;
  `bash scripts/check-no-placeholders.sh` exits 1; the repo deed still says
  `rsr-template-repo`; the GitHub About box and topics are empty. (A1, A2)
. **Kernel chain.** The obligations are discharged by a solver whose answer is
  trusted, not checked. Until a `.dk` survives three kernels, everything above
  `Warrant` is a promise. (K2–K9)
. **Theory width.** The checked theorem covers hazard sites in a store-free
  fragment: no store, no loops, no postconditions, no linearity lift. (T1–T4)
. **Estate conformance.** Atoma's Agda sits outside the proof manifest, so
  `just proof-check-agda` does not see it; the VC generator is Python, which the
  estate toolchain policy forbids; CI has no Atoma gate. (A3–A6)

== Invariants

These hold for every change, forever, unless the owner amends the specification.

[cols="1,5", options="header"]
|===
| ID | Invariant

| I1 | Core ABIs, AST/IR schemas and contract representations are Idris2 with `%default total`; zero `believe_me`, zero `assert_total`, zero `postulate`.
| I2 | Checker and VC-generator logic outside Idris2/Agda is Ada/SPARK or Rust-with-Creusot, strictly separated from untrusted CLI and process I/O.
| I3 | Agda semantics is `--safe --without-K`, inside the Dedukti-CIC subset: indexed inductives and structural eliminators; no inductive-recursion, no cubical, no rewrite rules.
| I4 | A witness is `.dk`, content-addressed by `BLAKE3` under `atoma.dk.v1`, and `INCOMPLETE (Warrant)` until **both** `coqchk` (zero extra axioms) and `lean4checker --fresh` accept it.
| I5 | ECHIDNA owns dispatch, solving and exchange; Proof Burrower owns the `.dk` cache. Atoma adds no solver runner.
| I6 | `[*c]T` is banned. `[*]T` exists only bound by an Idris2 ghost length. `@ptrFromInt`, arbitrary `@ptrCast`, `volatile`, inline `asm`, `@cImport`, mutable globals and unbounded recursion are quarantined or banned (spec §3).
| I7 | Every committed file has an SPDX header (`MPL-2.0` code, `CC-BY-SA-4.0` docs). Documentation is AsciiDoc. No `.md` under `docs/`.
| I8 | Every generated artefact is regenerated, not hand-edited: `spec/face-b.cspec` (G8), `docs/architecture/REPOSITORY-MAP.adoc`, the receipt.
| I9 | One name: Atoma. No `zigprove`, no `zp_`, no `ZPV1`, no second project name.
| I10 | Any claim added to the specification gets a row in the claims ledger, with a gate or an explicit `not checked`.
| I11 | No new implementation language outside the estate policy; no Python in a path the gates depend on after A6.
| I12 | `../spec/face-a.cspec` is normative text until F0.1 replaces it with `encode frameParse` output.
|===

== Environment

Atoma needs three toolchains that are not in a default image. The recipes below
were run on 2026-10-22 and are the ones to copy.

=== Tier 1 — a cold sandbox (ephemeral, no root)

`/tmp` does not survive a snapshot restore. Re-run this, then `./verify.sh`.

[source,bash]
----
# Zig 0.15.2 — the CLI is pinned to it (tools/atoma/.zig-version)
python3 -m venv /tmp/zv15
/tmp/zv15/bin/pip install ziglang==0.15.2
export PATH=/tmp/zv15/lib/python3.11/site-packages/ziglang:$PATH

# Agda 2.7.0.1 — pip wheel ships without the primitive library; fetch it
python3 -m venv /tmp/zv
/tmp/zv/bin/pip install agda==2.7.0.1 z3-solver pyyaml
# the wheel has no prim library; an empty libraries file means "no user libraries"
mkdir -p /tmp/zv/lib/python3.11/site-packages/agda/data/lib
: > /tmp/zv/lib/python3.11/site-packages/agda/data/lib/libraries
curl -L https://codeload.github.com/agda/agda/tar.gz/refs/tags/v2.7.0.1 |
  tar -xz -C /tmp --wildcards '*/src/data/lib/prim/*'
cp -r /tmp/agda-2.7.0.1/src/data/lib/prim \
  /tmp/zv/lib/python3.11/site-packages/agda/data/lib/

# run everything
export PATH=/tmp/zv15/lib/python3.11/site-packages/ziglang:$PATH
cd examples/atoma/frame-v1
AGDA=/tmp/zv/bin/agda ./verify.sh
----

Expected: twelve `ok` lines (G5 prints twice), `atoma 20 tests`, and a receipt
whose `status` is `INCOMPLETE` and `status_class` is `Warrant`. If `agda` is not
on `AGDA=`, G11 prints `not-run` — that is a correct outcome, not a failure, and
the receipt says `"proof":{"status":"not-run"}`.

=== Tier 2 — the estate

A minted repository uses `mise` + `just` instead of venvs:

[source,bash]
----
just setup            # installs the toolchain declared in mise.toml, then doctor
just doctor           # PASS/WARN/FAIL per tool; exits 1 on any FAIL
just proof-check-all  # idris2, lean4, agda, coq, plus scan-dangerous
just test             # provision::test
----

`mise.toml` currently declares `just`, `shellcheck`, `trivy`, `zig`. It does
**not** declare `agda`, `z3` or `idris2`; A4 is the task that closes that gap so
a fresh clone can run G7 and G11 without hand-built venvs.

=== Tier 3 — CI

No workflow runs an Atoma gate today. `quality.yml` runs the estate checks;
`verify.sh` is invoked only by a human. A5 adds
`.github/workflows/atoma-verify.yml` with pinned Zig, Agda and z3, running
`verify.sh` plus `just proof-check-agda`, uploading the receipt as an artefact,
and **failing** if the receipt says `not-run` for a tool the job installed.

=== Degradation matrix

[cols="2,2,3,2", options="header"]
|===
| Tool absent | Gate | What the gate does | What the receipt says

| `z3` | G7 | prints `G7 --` and continues | `"smt":{"status":"not-run","vcs":0}`
| `agda` | G11 | prints `G11 --` and continues | `"proof":{"status":"not-run","srcset":"none"}`
| `idris2` | F0.1 | does not exist yet (T5) | Face A remains `transcribed`
| `dkcheck`/`coqchk`/`lean4checker` | K-series | does not exist yet | `status_class` stays `Warrant`
| `zig` | everything | `verify.sh` dies at the first build | no receipt is written
|===

The asymmetry is deliberate: a missing solver weakens a *claim*, a missing
compiler stops *work*. Only the first is allowed to produce a receipt, and only
with the degradation visible in it.

Gate discipline, learned the expensive way:

* A gate that cannot run prints `not-run` and **never** `ok`.
* A gate is trusted only after the thing it guards has been broken deliberately
  and the gate was seen to fail. Each of G4, G5-probe, G10 and G11's grep exists
  for that reason.
* G7 and G11 are skip-capable by design; G1–G6, G8–G10 are not. If a machine
  cannot run a non-skip gate, the correct output is a failure, not a skip.

== Milestones

Six milestones, each with an exit gate. The dependency graph is a spine with
parallel tracks: A must land before the repo can be read as Atoma; K is the only
road to `COMPLETE`; T can proceed in parallel with A and K because it needs only
Agda; S, C and H come after.

....
A (identity, 2–3 days) ──► K (kernel chain, 3–6 weeks) ──► S (subset)
   │                              │
   └────────────► T (theory, ongoing, unblocked) ──► C (cost/secrecy)
                                  │
                                  └──► H (hardening, ecosystem)
....

[[board]]
[cols="1,2,3,2", options="header"]
|===
| Milestone | Goal | Exit gate | Status

| A | The repository *is* Atoma, and the estate gates see its proofs | `check-no-placeholders.sh` exits 0; `just proof-check-agda` includes 4 modules; CI runs `verify.sh` | `todo`
| K | One VC reaches `COMPLETE (Receipt)` through three kernels, then fourteen | G12, G13, G14, G15 on one VC, then the full set | `blocked` (needs idris2, dkcheck, echidna, coqchk, lean4checker)
| T | The theorem covers store, loops and postconditions | `agda --safe --without-K` on the extended `Core`/`Soundness`; no postulates | `todo` (unblocked)
| S | Phase 2: regions, allocators, recursion, borrows beyond the signature | a second worked example verified end to end | `todo`
| C | Phase 3: MaxPlus bounds, stack HWM, secrecy lattice | a secret-dependent branch rejected; a padding leak rejected even when memory safety passes | `todo`
| H | Proof Burrower cache, badges, more examples, release | cache hit skips recheck only on TCB match; badge names phase + digest | `todo`

[[A3]]
=== A3 — Register the metatheory with the estate proof gate

*Status:* `todo` · *Size:* S · *Owner:* agent

*Why.* `just proof-check-all` is the estate's single source of truth for "do the
proofs compile", and it cannot see Atoma's proof. `verification/proofs/agda/MANIFEST`
lists exactly one module:

[source]
----
verification/proofs/agda|Properties.agda|gated| compiles under `agda --safe`
----

The four Atoma modules live at `verification/atoma/agda/` and are checked only
by `check-agda.sh`, which nobody's CI calls. A proof outside the manifest is
gated by memory.

*Method.* Two changes, both small:

. Add to `verification/proofs/agda/MANIFEST`, using the format's existing
  arbitrary-source-root support:
+
[source]
----
verification/atoma/agda|Bv.agda|gated| bitvector bridge; Atoma spec §4.5
verification/atoma/agda|Lin.agda|gated| linear handles; spec §3.6
verification/atoma/agda|Core.agda|gated| core language + VC generator; spec §6.1–6.2
verification/atoma/agda|Soundness.agda|gated| the §6.3 theorem
----
. Teach `scripts/check-proofs.sh` per-entry flags, because the estate invokes
  `agda --safe` and Atoma additionally requires `--without-K`. Extend the
  manifest line with an optional fifth field (`flags=--without-K`) and pass it
  through; default stays as today.

*Accept.* `just proof-check-agda` (or `bash scripts/check-proofs.sh agda`)
checks five modules including all four Atoma ones, and
`bash scripts/scan-dangerous.sh` exits 0 on the new files.

*Falsifier.* Add `postulate`-like cheating to a copy of `Soundness.agda` and
confirm **both** `check-proofs.sh` and `check-agda.sh` reject it. If only one
does, the two checkers disagree and the weaker one is decorative.

*Note.* Moving the files under `verification/proofs/agda/atoma/` is the
alternative. It is more churn (six documented paths and the spec's repository
map) for no additional guarantee, and the proof `srcset` digest would not change
because it hashes contents, not paths. Prefer the manifest entry.

[[A4]]
=== A4 — Declare the Atoma toolchain in the provisioning contract

*Status:* `todo` · *Size:* S · *Owner:* agent

*Why.* `mise.toml` declares `just`, `shellcheck`, `trivy`, `zig` and nothing
else. A fresh clone therefore cannot run G7 or G11 without hand-built venvs, and
`just doctor` reports a healthy environment that cannot verify anything.

*Method.* Declare `agda` and `z3` in `mise.toml`: as mise tools if the registry
carries them, otherwise as a pinned download with a recorded checksum. The
venue matters less than the pin — `just doctor` must be able to answer PASS or
FAIL for each, and `mise.lock` must make the answer the same on every machine.
Add `[env]` entries for `AGDA` so
`verify.sh` finds them without a hand-built venv, then `just toolchain-refresh`
to re-lock.

*Accept.* On a clean container, `just setup && just doctor` passes and
`./verify.sh` reports G7 `ok` and G11 `ok` without any manual `export`.

*Falsifier.* The tools appear in `mise.toml` but a fresh `mise install` still
leaves `verify.sh` printing `not-run` for G7/G11 — the declaration is decorative.

[[A5]]
=== A5 — Put the gates in CI

*Status:* `todo` · *Size:* M · *Owner:* agent

*Why.* Every gate in this repo runs because a human typed `./verify.sh`. The
estate's own history is explicit that path-filtered, skip-happy CI is how
non-compiling proofs survive for months.

*Method.* Add `.github/workflows/atoma-verify.yml`:

[source,yaml]
----
# sketch — the pinning and checksum conventions come from actions.lock
jobs:
  verify:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@<pinned>
      - run: just setup            # or mise install with a pinned lockfile
      - run: just doctor
      - run: cd examples/atoma/frame-v1 && ./verify.sh
      - run: just proof-check-agda
      - uses: actions/upload-artifact@<pinned>
        with: { name: phase0-receipt, path: examples/atoma/frame-v1/witness/ }
      - name: no silent not-run
        run: |
          jq -e '.smt.status == "discharged" and .proof.status == "checked"' \
            examples/atoma/frame-v1/witness/phase0.receipt.json
----

The last step is the point of the job: in CI the tools *are* installed, so a
`not-run` is a failure rather than a degradation.

*Accept.* A pull request that breaks G8 (edit `spec/face-b.cspec` by one
character) goes red; a pull request that touches nothing stays green; the
receipt is downloadable from the run.

*Falsifier.* The job passes with `jq` removed, or with `verify.sh` stubbed to
`exit 0`. Both must be tried once, deliberately.

*Why.* `mise.toml` states the estate policy — "no python, node/npm/yarn, make or
nix here" — and `vc/gen_vcs.py` was the only thing standing between the
repository and a self-contained `verify.sh`. It was also the VC generator, i.e.
exactly the component the specification says must eventually live in Ada/SPARK or
Creusot-verified Rust, not in a scripting language.

*Method as executed.*

. Port the 14 obligations into `tools/atoma/src/vc.zig`, exposed as
  `atoma vc <outdir> [--cspec FILE]`. The generator is untrusted plumbing (§1 of
  the spec), so Zig is acceptable for now; the trusted path remains T6.
. Delete `vc/gen_vcs.py`. G7 now runs the Zig binary, then z3, then compares each
  verdict with the reviewed table `vc/expected.tsv`.
. Bind the generator to the contract: `--cspec` canonicalises the contract and
  refuses to emit anything unless the five facts the queries encode are still
  present verbatim (`checkContract` in `vc.zig`). G7 exercises that refusal with
  a deliberately drifted contract, so the binding cannot be vacuous.

*Postscript — the original acceptance criterion was unachievable, and that was
informative.* It asked for the 14 `.smt2` files to be byte-identical to the
Python-era ones. They could not be: those files were `z3`'s `sexpr()` dump of a
Python-built AST (`(let ((?x60 …))`) — machine-specific variable numbering, not
reviewable text — so byte-identity would have required reproducing the dump,
which is what the card's own falsifier forbids ("reproduces the files because it
embeds their text"). The honest resolution was to change the artefact: the Zig
generator emits hand-readable SMT-LIB, so the VC-set digest necessarily moved
from `blake3:72c74c01…5e3698` to `blake3:dec3d833…9ce35d`. The obligations,
the 8/6 unsat-sat split and every verdict are unchanged. The stale-digest check
in G7 (`cmp` against regenerated output) is what makes this safe going forward:
a `.smt2` in the tree that the generator would not produce is a hard failure.

*Accept (as achieved).* `./verify.sh` runs G7 with no Python on PATH; 14/14
verdicts match `vc/expected.tsv`; a drifted contract is rejected; a hand-edited
`.smt2` fails the gate.

*Falsifier, re-run.* Mutating `requires ( <= 12 ( len input ) )` to `<= 11`
stops generation with `CONTRACT-DRIFT` and exit 1. Embedding the query text
instead of deriving it would still pass the `cmp` check — the residual weakness,
recorded here rather than hidden: the queries are derived from the *contract
facts*, but the obligations themselves are still hand-derived from §7, not
computed from a core IR. T6 is where that gap closes.

[[track-t]]
== Track T — Theory completion

Unblocked in this environment and the highest-value work available to an agent
without ECHIDNA. Each task ends in Agda that checks under `--safe --without-K`,

[[T1]]
=== T1 — The store, and the framing lemma

*Status:* `todo` · *Size:* L · *Owner:* agent

*Why.* `Core.agda` is store-free because a store makes `soundness` unprovable
without a framing lemma. Stating it, rather than dodging it, is the next step;
`exec-id` then becomes a special case instead of the whole story.

*Method.* Add `assign : Nat → Tm → Stmt` and a store `σ : Nat → Nat`.
Define `writes : Stmt → List Nat` and `reads : Fm → List Nat`, prove
`frame : disjoint (writes s) (reads pc) → ⟦ pc ⟧f σ → ⟦ pc ⟧f (exec s σ)`,
and re-prove `soundness` for the extended fragment. Keep `exec-id` as a
corollary of `frame` when the statement writes nothing.

*Accept.* `Soundness.agda` checks; the theorem type now quantifies over the store
and carries the disjointness premise; the old store-free theorem remains as a
corollary so nothing that depended on it breaks.

*Falsifier.* Prove `frame` by restricting `writes` to constants, or by making
`reads` empty. If the lemma holds for a statement that writes a variable the
path condition mentions, the model is wrong — test with `assert (x ≤ 5) ; x := 9`.

[[T2]]
=== T2 — Loops

*Status:* `todo` · *Size:* L · *Owner:* agent

*Why.* `while e inv I dec V do s` is the construct that makes `MAX_ITERS` and
MaxPlus meaningful, and it is the one the specification promises in §3.6.

*Method.* Add the statement, the three VCs (establishment, preservation, exit),
and termination via an explicit fuel argument — `--safe` rejects well-founded
recursion, so the fuel is a parameter, not a hack. Prove: if the invariant holds
and the variant strictly decreases on every iteration, then `run n s` is safe for
`n` iterations and the postcondition holds on exit.

*Accept.* The extension checks; a worked loop (`while (i < len)` over the frame
payload) is proved with its invariant; the fuel theorem is stated with its bound.

*Falsifier.* An invariant that is preserved but not strong enough to imply the
exit condition. The theorem must fail for that invariant — check by weakening it
deliberately.

[[T3]]
=== T3 — Postconditions and error paths

*Status:* `todo` · *Size:* M · *Owner:* agent

*Method.* Model outcomes (`ret ok`, `err c`) and prove the two clauses of
`soundness-full` (2) and (3) for the extended fragment: `pre ∧ res = ok ⟹ φ`
and `pre ∧ res ≠ ok ⟹ ψ`.

*Accept.* `soundness-full`'s (1)–(3) are proved; (4) and (5) remain cited from
`Lin`/`T4`.

*Falsifier.* A postcondition that holds only because `err` is unreachable in the
model. Make an error path reachable and confirm the clause becomes non-trivial.

[[T4]]
=== T4 — Lift linearity over the statement structure

*Status:* `todo` · *Size:* M · *Owner:* agent

*Why.* `Lin.agda` proves `exactly-once` for a modelled scope; `soundness-full`
needs it for *the* statement language, which currently has no `acquire`/`release`.

*Method.* Add the two statements, give `St` a place in the configuration, and
prove `consumed-exactly-once s σ` by structural induction, reusing
`Lin.exactly-once` at the `defer`/`errdefer` boundary.

*Accept.* Clause (4) of `soundness-full` is proved for the extended fragment.

*Falsifier.* The proof accepts a program with two `release`s on one path. Try

premise, not by a side condition nobody checks.

== Definitions of done

=== A task is done when

. The acceptance command was run and its output is quoted in the commit message
   or the receipt.
. The falsifier was attempted and the failure was observed (for gates and
   checkers, at least once ever, and recorded in the task card).
. Any generated artefact was regenerated (`face-b.cspec`, repo map, receipt).
. The specification's claims ledger row, if any, still says the truth.
. No new `{{PLACEHOLDER}}`, no `.md` under `docs/`, no missing SPDX header.

=== A gate is done when

. It fails when the thing it guards is broken — demonstrated, not assumed.
. A missing tool produces `not-run`, never `ok`.
. Its output appears in the receipt, or the receipt records why not.

=== A receipt is honest when

. `status_class` is `Receipt` **only** if every witness has three kernel
   verdicts over one `.dk` digest (I4).
. Every `not-run` is visible and attributable to a named missing tool.
. The TCB is named: tool, version, and hash for each checker.
. The digests it cites can be recomputed by `verify.sh` on a fresh clone.

=== A milestone is done when

. Its exit gate is green on `main` in CI, not only locally.
. The specification has been amended in the same release if the milestone
   changed a claim (I10).
. This plan's status board says `done (evidence: …)` with a commit and a gate.

=== A specification change is done when

. The claims ledger gains or updates a row.
. Every `§`-reference still resolves (the ledger is unnumbered front matter; the
   first numbered section is Executive architecture).
. `docs/spec/ATOMA-SPEC.adoc` renders: `npx @asciidoctor/core` or any
   Asciidoctor, with no new warnings; tables balanced.

== Change protocol

=== Branches, commits, receipts

* Work on a branch; the session branch is `arena/4f8f5ab1-zigprove` and is
  never renamed. Do not create or push other branches.
* A commit that changes a gate says which gate and quotes the new output.
* A commit that changes a claim updates the ledger in the *same* commit.
* `witness/` is committed. Build caches are not (`.zig-cache/`, `zig-out/`,
  `*.agdai`, `build/`, `node_modules/`).
* Never force-push a branch others may have based work on.

=== How to change this plan

Add or amend a task card, keep its ID, and record the reason in the card. If the
change moves a milestone's exit gate, it needs an ADR in `docs/decisions/` and a
matching amendment to `docs/spec/ATOMA-SPEC.adoc` §10.
